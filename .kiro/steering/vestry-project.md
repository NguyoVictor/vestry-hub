# Vestry — Project Steering

## App Overview
Vestry is a multi-tenant Church SaaS platform. It is comparable to ChurchSuite and Planning Center. Each church is a separate tenant identified by church_id.

## Tech Stack
- React + TypeScript + Vite
- Supabase (PostgreSQL, RLS, Edge Functions, Realtime, Storage)
- Tailwind CSS + shadcn/ui
- React Router v6
- TanStack Query v5 (all data fetching — never useEffect + useState for data)
- React Hook Form + Zod (all forms + validation)
- Lucide React (all icons)
- Recharts (all charts)
- react-helmet-async (dynamic page titles)
- Sonner (all toast notifications)
- date-fns (all date formatting)
- papaparse (CSV import/export)

## Supabase Conventions
- Always filter every query by church_id from useChurch() context
- Never fetch data across churches
- Use the typed Supabase client generated by supabase gen types typescript
- All queries use useQuery hooks from TanStack Query
- All mutations use useMutation with onSuccess calling queryClient.invalidateQueries
- Never expose secret keys to the frontend — all sensitive operations go through Supabase Edge Functions
- All tables must have RLS enabled with appropriate policies

## Naming Conventions
- Components: PascalCase (e.g. MemberProfile.tsx)
- Hooks: camelCase with use prefix (e.g. useChurch.ts)
- Utilities: camelCase (e.g. formatCurrency.ts)
- Pages: PascalCase matching the route (e.g. MembersPage.tsx)
- Database tables: snake_case (e.g. church_members)
- Query keys: array format ['entity', id] (e.g. ['members', churchId])

## Performance Rules
- Always set staleTime: 300000 (5 min) on all useQuery hooks
- Always use lazy() + Suspense for all page-level route components
- Always use lazy() for Recharts, ReactPlayer, ReactBigCalendar, TipTap
- Never import heavy libraries at the top level of a page component
- Always create compound Supabase RPC functions for pages with 4+ stat queries
- Always add indexes on church_id for every new table created
- refetchOnWindowFocus: false globally on QueryClient

## ⚠️ CRITICAL — ACTUAL DATABASE SCHEMA (OVERRIDES ALL PHASE SPECS)

The phase spec files (phase-1 through phase-9) were written before the
database was built. Kiro built the database with different names than
the specs defined. The actual database is the source of truth.
ALWAYS use the actual database names below — NEVER use the spec names.

### ID Type Override
All IDs in the database are VARCHAR not UUID.
Never use gen_random_uuid() — use the existing ID generation pattern.

### The TABLES and COLS Constants Are Mandatory
Every single Supabase query MUST use the constants from `src/lib/schema.ts`.
Never hardcode table names or column names as strings in any component,
hook, or utility. Always import from schema.ts:
```typescript
import { TABLES, COLS } from '../lib/schema'

// correct
supabase.from(TABLES.DONATIONS).eq(COLS.CHURCH_ID, tenantId)

// WRONG — never do this
supabase.from('donations').eq('church_id', churchId)
```
